# Learn layer: layered solutions and interactive scenes (spec, 30 Sept 2026)

Two additions to every clean item, so a student can choose how slowly a solution is explained and, where a
picture helps, see and manipulate the idea the question tests. Both are generated by our own prompts from our own
items (no board text), gated deterministically, and stored on the item file so the pack build carries them.

## 1. Solution levels (`parts[i].solution_levels`)

Three depths of the same solution. `standard` is the existing `parts[i].solution` (kept as is). The new ones:

```json
"solution_levels": {
  "brisk": [
    {"step": 1, "working": "$-x^2+8x-5=x+1 \\Rightarrow x^2-7x+6=0 \\Rightarrow x=1,\\,6$", "secures": ["M1", "A1"]}
  ],
  "every_step": [
    {"step": 1, "working": "$-x^2 + 8x - 5 = x + 1$", "why": "The curve and the line meet where their y-values are equal, so set the two expressions equal.", "secures": "M1", "check": "Substitute x = 1 into both sides: both give 2."},
    {"step": 2, "working": "$0 = x^2 - 7x + 6$", "why": "Move everything to one side so the quadratic equals zero. Adding $x^2$, subtracting $8x$ and adding $5$ to both sides.", "secures": null, "check": null}
  ]
}
```

Rules:
- `brisk`: what a strong student would actually write in the exam. One entry per mark or pair of marks; every scheme
  code of the part appears in exactly one `secures` list, in scheme order. No prose beyond a word or two.
- `every_step`: every algebraic manipulation written out as its own line (no "simplifying gives"), each with a
  plain-words `why` (one or two sentences, second person, no jargon without a gloss). `secures` is the scheme code
  the line earns, or null. `check` is an optional one-line way to verify the line (substitute back, differentiate
  back, units, sign). Typically 2 to 4 times as many lines as `standard`.
- LaTeX in `$...$` only (`$$...$$` for display). Our words. No board names, no "examiners".
- Gates (deterministic, `scripts/clean/gate_levels.py`): every `$...$` renders in KaTeX; G7 copy check on all text;
  `secures` codes exist in the part's scheme and brisk covers each code exactly once; the last `working` of each
  level contains an expression sympy finds equivalent to each of the part's `answers` (where the answer is a
  closed form; skip worded parts); every `why` is non-empty for every_step; no banned words.

## 2. Scenes (`parts[i].scenes` or item-level `scenes`)

A scene is a JSON description of an interactive JSXGraph figure plus a short guided walk-through. The model writes
the description; the browser renders it (`chatbot/static/scene.js`). The model never writes code.

```json
{
  "id": "cr-area-between-curve-and-line-core::-::1",
  "part": null,
  "title": "Why the area is curve minus line",
  "purpose": "See that the curve is above the line between the intersections, so the area is the integral of (curve - line).",
  "approach": "graphical",
  "board": {"x": [-1, 8], "y": [-2, 12], "axis": true, "grid": true, "aspect": "auto"},
  "params": [
    {"id": "k", "label": "upper limit k", "min": 1, "max": 6, "step": 0.1, "value": 3}
  ],
  "elements": [
    {"type": "function", "id": "C", "expr": "-x^2 + 8*x - 5", "color": "primary", "label": "C"},
    {"type": "function", "id": "l", "expr": "x + 1", "color": "secondary", "label": "l"},
    {"type": "point", "id": "A", "x": "1", "y": "2", "label": "(1, 2)"},
    {"type": "point", "id": "B", "x": "6", "y": "7", "label": "(6, 7)"},
    {"type": "integral", "id": "R", "between": ["C", "l"], "from": "1", "to": "k", "color": "primary", "opacity": 0.25},
    {"type": "text", "id": "areaLabel", "x": "6.5", "y": "10", "value": "Area so far = {area(R)}"},
    {"type": "glider", "id": "Q", "on": "C", "x": "3", "label": "Q"}
  ],
  "steps": [
    {"n": 1, "text": "The shaded region grows as you drag $k$ to the right. It is bounded above by $C$ and below by $l$.", "set": {"k": 3}, "show": ["R"]},
    {"n": 2, "text": "Drag $k$ to $6$: the region closes at the second intersection, and the area reads $\\frac{125}{6} \\approx 20.8$.", "set": {"k": 6}},
    {"n": 3, "text": "Drag $Q$ along $C$ between $x=1$ and $x=6$: its $y$-value is always above the line's, which is why we integrate (curve $-$ line), not the other way round.", "highlight": ["Q"]}
  ],
  "links": {"solution_steps": [3, 4], "marks": ["M1", "dM1"], "pitfalls": ["area-between-wrong-subtraction"]}
}
```

### Expression grammar (for `expr`, `x`, `y`, `from`, `to`, `value` templates)
Numbers; the variable `x` (or `t` for parametric); parameter ids; `+ - * / ^ ( )`; functions `sin cos tan asin acos
atan sinh cosh tanh exp ln log sqrt abs floor` (one argument each); constants `pi`, `e`. Implicit multiplication is
NOT allowed (`2*x`, not `2x`). Angles in radians. A `text.value` may embed `{expr}` placeholders evaluated live, plus
the special `{area(ID)}` for an integral element's current value and `{x(ID)}`, `{y(ID)}` for a point's coordinates.

Statistics helpers (added 23:30, 30 Sept; three arguments each, separated by commas; each argument is itself an
expression and may use params; `n` and `k` are rounded to integers): for $X \sim \mathrm{B}(n, p)$,
`binom_pmf(n, p, k)` $= \mathrm{P}(X=k)$, `binom_le(n, p, k)` $= \mathrm{P}(X \leqslant k)$, `binom_ge(n, p, k)`
$= \mathrm{P}(X \geqslant k)$; for $X \sim \mathrm{N}(\mu, \sigma^2)$, `norm_cdf(x, mu, sigma)` $= \Phi((x-\mu)/\sigma)$,
`norm_pdf(x, mu, sigma)` and `norm_inv(q, mu, sigma)` (the inverse of `norm_cdf` in `x`). Example placeholder:
`{binom_le(10, 0.3, k)}`. Commas are allowed nowhere else; a wrong argument count is rejected
(`norm_cdf(1)`: "function norm_cdf takes 3 arguments (got 1)"). Out-of-domain arguments ($p \notin [0,1]$, $\sigma
\leqslant 0$, $q \notin (0,1)$, $n > 10^5$) give NaN, which the gate's finiteness check rejects and the renderer
prints as `?`. Runtime: `SCENE_STATS` in `scene_compile.js` (log-gamma binomial terms, erfc to ~1e-14, Acklam's
inverse plus one Halley step; the compiled function receives it as `S`, so no global lookup). Gate: sympy Function
subclasses that collapse to a Float once the arguments are numeric (`gate_scene.STAT_FUNCS`), evaluated through
`gate_scene.NUMERIC` in lambdify. Poisson is not in 9MA0, so there is no `poisson_*`.

### Element types
| type | fields | renders as |
|---|---|---|
| `function` | `expr`, optional `domain: [a, b]`, `color`, `label`, `dash` | curve y = f(x) |
| `parametric` | `x_expr`, `y_expr`, `t_range: [a, b]`, `color`, `label` | parametric curve |
| `point` | `x`, `y` (expressions; may use params), `label`, `draggable` (default false), `color` | fixed or draggable point |
| `glider` | `on` (id of a function/parametric/segment/circle), `x` (start), `label` | point the student drags along a curve |
| `segment` / `line` | `from: [x, y]`, `to: [x, y]` (expressions or point ids), `dash`, `color`, `label` | segment or infinite line |
| `tangent` | `at` (point or glider id), `of` (function id), `color` | tangent line at that point, moves with it |
| `normal` | same as tangent | normal line |
| `integral` | `of` (function id) or `between: [f, g]`, `from`, `to`, `color`, `opacity` | shaded area, value available as `{area(ID)}` |
| `vector` | `from: [x, y]`, `to: [x, y]`, `label`, `color` | arrow |
| `circle` | `centre: [x, y]`, `radius`, `color` | circle |
| `polygon` | `points: [[x, y], ...]` or point ids, `color`, `opacity` | filled polygon |
| `text` | `x`, `y`, `value` (may hold `{...}` placeholders and `$...$` LaTeX), `color` | live label |
| `vline` / `hline` | `at` (expression) | dashed guide line |

Colours are tokens: `primary`, `secondary`, `success`, `warning`, `muted`, `mark`. The renderer maps them to the
site's CSS variables (dark mode aware).

### Steps
`steps[].text` is shown one at a time with Previous/Next. `set` moves sliders; `show`/`hide` toggle element
visibility by id; `highlight` briefly emphasises elements. Every scene has 2 to 5 steps.

### `approach`
`graphical` (the picture is the argument), `algebraic-check` (the picture verifies an algebraic result, e.g. roots
as crossings) or `model` (a mechanics or statistics model, e.g. a projectile path with a launch-angle slider).

### Gates (`scripts/clean/gate_scene.py`, deterministic)
- Every expression parses with sympy after `^` -> `**`, and its free symbols are within `{x, t}` plus the scene's
  param ids; no implicit multiplication; only whitelisted functions, each with exactly its arity (commas only between
  a helper's arguments); the statistics helpers are evaluated numerically at the default params and must be finite.
- Every id referenced (`on`, `at`, `of`, `between`, `show`, `hide`, `highlight`, point ids in `from`/`to`) exists;
  ids are unique; types are from the table.
- Board ranges are finite and ordered; params have min < max, step > 0, value within range.
- Functions are finite at 9 sample points across the board x-range (or across `domain`), so nothing blows up.
- `steps` has 2 to 5 entries; all `$...$` in `text` and `value` render in KaTeX; G7 copy check on all text; no banned
  words; `links.marks` are codes of the part's scheme; `links.pitfalls` are error codes on the item.

### Renderer (`chatbot/static/scene.js`)
`renderScene(containerId, scene, {theme})` creates the JSXGraph board (lazy: only when the container is visible,
`setTimeout(..., 50)` after reveal), compiles expressions with a whitelist tokeniser (never `eval` of raw model
text: tokens outside the grammar are rejected and the scene shows an error card), builds sliders for `params`,
creates elements in order, wires the steps UI, and returns `{board, setParam, showStep}`. Sliders live in a row
above the board; the steps text sits below with Previous/Next. Mobile: the board is 100% width, height 320 to 420px.

### Guide (added 23:05, 30 Sept: every scene must explain itself)
A student must know what each drawn thing is, exactly how to interact, and how the picture links to the question.
Each scene carries a `guide` block; the renderer shows it around the board and falls back to defaults built from the
elements when a field is missing.

```json
"guide": {
  "what_you_see": "One or two sentences: what the picture shows in the question's own terms (the curve C, the line l, the shaded region R).",
  "legend": [
    {"id": "C", "meaning": "The curve $y=-x^2+8x-5$ from the question."},
    {"id": "R", "meaning": "The region whose area the question asks for; it grows as you move $k$."}
  ],
  "interact": [
    {"control": "k", "kind": "slider", "do": "Drag the slider to move the upper limit from $1$ to $6$.", "watch": "The shaded area and the live reading grow; at $k=6$ the reading is $\\frac{125}{6}\\approx 20.8$."},
    {"control": "Q", "kind": "glider", "do": "Drag $Q$ along the curve.", "watch": "Its $y$-value stays above the line between $x=1$ and $x=6$."}
  ],
  "question_link": {"part": null, "marks": ["M1", "dM1", "A1*"],
                    "text": "The shaded region is $R$. Its area is what the 5-mark part asks you to show equals $\\frac{125}{6}$; the integral you set up (M1) and evaluate (dM1) is the area you are watching."},
  "read_off": ["The live label 'Area so far' is the value of the integral from $1$ to $k$."]
}
```

Rules: every element with a `label` or that is an integral, glider, draggable point, tangent, normal or vector has a
legend entry; every param and every glider or draggable point has an `interact` entry; `question_link.marks` are codes
of the part's scheme; texts are our words, `$...$` for maths, no board names. Gate (`gate_scene`): ids exist, coverage
as above, KaTeX renders, banned words, G7 copy check. Renderer: a legend row with colour swatches under the board, a
"How to use this" box listing the controls, a "How this links to the question" box, and `read_off` as small print.
